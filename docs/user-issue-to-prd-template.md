# AI智能体：用户问题转需求分析模板

> 适用场景：AI智能体平台，处理用户反馈、推文收集到的问题，区分：用户使用问题、产品Bug、大模型固有局限，选择「推文教程」或「输出需求文档」两种处理路径

## 整体处理流程

拿到用户反馈现象 → 结合自身产品使用经验初步判断 → 尝试复现问题 → 归类问题类型 → 选择对应解决方案

### 1、问题记录（原始现象，不做主观加工）

- 用户原始现象描述：
- 问题来源：推文踩坑收集 / 个人实操发现 / 团队内部反馈
- 复现操作步骤：尽可能写出完整可复现操作链路

### 2、问题三分类判断（核心判断逻辑）

#### A类：用户不会使用（操作、理解层面问题）

👉判断依据：
结合本人高频使用产品的经验，该现象可以通过调整操作流程、调整输入、调整参数规避；产品本身功能无异常。

✅处理方案：**不输出需求文档，沉淀到公众号推文/使用教程，补充详细复刻操作步骤，教会用户正确使用**

#### B类：产品Bug（产品本身功能缺陷）

👉判断依据：
排除操作问题之后，手动测试，问题可以稳定复现，不是偶现现象，属于程序、交互、流程层面缺陷。

✅处理方案：输出正式需求/缺陷文档，提交开发进行修复。

#### C类：大模型固有局限

👉判断依据：
功能流程正常可跑通，但大模型输出结果质量差、幻觉、输出不稳定；产品流程没有故障，根源来自底层大模型能力边界。

✅处理方案：不改动产品代码，给用户实操建议，例如更换底层大模型、调整提示词、调整输入内容来缓解问题。

### 3、优先级简易判断（小众产品，缺少海量用户反馈）

1. 问题可以稳定复现，影响多篇推文推广的热门智能体 → 优先级高，优先提交需求
2. 仅个别场景触发，影响面很小 → 记录留存，等待后续版本迭代
3. 属于大模型本身能力边界：只做用户引导，不排开发迭代

### 4、输出物选择

1. 📕输出推文教程：A类（用户不会使用）
2. 📄输出需求文档提交开发：B类（可稳定复现产品bug）
3. 💡使用建议给到用户：C类（大模型固有局限，更换模型/调整输入）

## 实战示例

> 用户问题：使用脚本生成智能体，输出的分镜表格经常格式错乱

1. 复现：按照用户操作步骤完整复现场景
2. 判断：
   - 如果是用户输入指令写的很乱，导致输出异常 → A类，推文补充输入示例与操作步骤
   - 如果同样输入，无论怎么调整，产品都会把表格解析错乱，稳定复现 → B类，输出需求文档提交开发修复
   - 如果流程正常，只是内容逻辑天马行空，表格格式没问题但是内容胡说八道 → C类，建议用户切换更强的大模型，优化提示词

## 个人复盘思考

AI产品和传统软件不一样，不是所有用户反馈都要改代码。
很多问题不需要开发介入，通过**用户教育（推文、教程）就可以解决；只有稳定复现的产品缺陷，才需要输出需求文档交给开发修复。
遇到大模型输出质量问题，产品侧无法彻底根除，只能通过引导换模型、优化提示词做缓解。
