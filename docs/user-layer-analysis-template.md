# AI智能体C端用户分层与落地判断模板

> 背景：产品处于增长阶段，缺少完整用户行为埋点，用户感知来源：模拟小白端到端测试、社群反馈、内部同事使用反馈、用户问卷。

## 一、四类C端用户画像&核心诉求

1. **下载尝鲜小白（新用户）**
   - 来源：朋友推荐、网络教程、官网案例吸引，新用户拥有免费额度。
   - 核心诉求：**零成本快速解决当下具体问题，希望上手简单，少学习成本。**
   - 典型痛点：找不到智能体入口，不清楚操作路径，不熟悉产品基础逻辑。

2. **高频实操普通使用者**
   - 核心诉求：直接使用平台现成智能体，不想自己调试提示词，追求直接拿到较好的输出效果，看重智能体库丰富度。

3. **深度玩家（提示词定制用户）**
   - 核心诉求：喜欢修改提示词、自定义搭建智能体，追求定制化能力，愿意折腾调参。
   - 典型痛点：高阶功能、自定义工作流编排相关的问题。

4. **一次性问题解决用户**
   - 核心诉求：只解决某一个特定任务，希望一次运行就拿到可用结果，不愿做多次调整。

## 二、在缺少大数据埋点下，如何感知用户诉求

> 局限：社群活跃用户是小部分固定人群，公众号处于冷启动，样本有限。

获取信息的途径：
1. 模拟小白视角，做端到端全流程用户侧测试，站在普通用户角度走完整使用链路。
2. 粉丝微信群观察用户提问，收集真实疑问。
3. 内部同事的使用反馈。
4. 官方问卷收集用户改进建议。

> 落地案例：官网案例视频引来用户咨询如何复刻，据此产出对应公众号教程推文。

## 三、不同用户，同一智能体的典型踩坑差异

1. **小白用户**：找不到智能体入口、不清楚基础操作流程，属于入门路径类问题。
2. **普通使用者**：智能体输出达不到预期，不知道怎么调整输入获得更好结果。
3. **深度玩家**：自定义提示词、工作流编排、高阶定制相关的问题。
4. **一次性用户**：对输出质量容忍低，期望一次运行就得到完美结果。

## 四、用户分层如何指导公众号推文/教程产出

> 现实约束：不分开写两套文章，**单篇推文同时覆盖小白+普通使用者**

1. 照顾小白：提供完整、连贯、无跳跃的跟做操作步骤，降低入门门槛。
2. 照顾普通使用者：重点展示运行效果、高频踩坑与解决方案。
3. 文章结构：痛点引入 →效果展示 →问题解决方案 →完整操作步骤 →踩坑汇总。

> 深度玩家内容不作为推文重点，推文主要面向小白与普通使用者。

## 五、用户分层辅助判断问题&需求优先级

拿到用户反馈，完成问题复现之后，结合用户分层做判断：
1. 如果是**小白高频踩坑**：优先通过推文、教程做用户教育；如果同时是大量新用户都会遇到的产品交互缺陷，则输出需求文档。
2. 如果是**深度玩家才会遇到的高阶问题**：评估受影响用户规模，影响面小则记录留存，不优先排期；影响较大再输出需求。

> 通用流程：复现问题 →识别该问题主要发生在哪一类用户 →判断：教程引导即可 / 需要输出产品需求文档。

## 六、典型真实案例

1. 用户反馈"没有页面模式切换功能"
   复现后发现：功能存在，只是小白找不到入口。
   处理：不输出需求，推文补充操作指引，靠用户教育解决。

2. 用户反馈"大模型生成效果很差"
   复现发现：用户输入提示词简短模糊，不是产品本身缺陷。
   处理：推文踩坑板块补充提示词撰写建议，引导用户优化输入。

## 七、小众产品做用户分层的风险与规避

### 风险

缺少大规模用户样本，仅靠社群、个人测试容易被小部分活跃用户的观点误导，产出的内容、判断存在片面、过时的风险。

### 规避手段

1. 不能只依靠个人主观感受，持续跟进社群用户提问、问卷反馈，做多源信息交叉校验。
2. 出现用户反馈，优先自己上手复现，再下判断，不直接把用户口头诉求直接转化为产品需求。
3. 区分：活跃用户的个人偏好 vs 广大普通用户的共性问题。
